# BOSS 海投助手

BOSS 直聘自动投递浏览器扩展（Manifest V3）。自动滚动岗位列表、按条件筛选、逐条投递，并结合大模型为**每一条岗位 JD** 生成定制招呼语。

> 本项目基于上游开源项目（AGPL-3.0）的**单文件版本**重构而来：原实现是一个约 2500 行的 `content.js`，现已拆分为 10 个职责清晰的模块，并配套 **11 组自动化验证套件 + 48 个变异测试**。

---

## 这个项目做了什么工程改造

上游版本是单文件 2500 行的 `content.js`，没有测试、没有类型、选择器散落各处。本次改造的重点：

| 问题 | 处理方式 |
|---|---|
| 单文件 2500 行，改一处怕崩全局 | 拆成 10 个模块，按 `content_scripts` 声明顺序加载，通过 `globalThis.__BH__` 命名空间通信 |
| 页面选择器散落在各处，失效难定位 | 收敛到 `05-selectors.js` 单一来源，并标注每个选择器的验证状态（已确认/待确认） |
| 无任何测试，改动全凭手感 | 建 11 组套件，共 500+ 断言，覆盖筛选逻辑、投递链路、AI 请求、存储容错、DOM 结构 |
| 「测试全绿」但可能测不到东西 | 引入**变异测试**：故意注入 48 个缺陷，验证测试真的会失败 |
| `localStorage` 数据损坏导致面板整体挂掉 | 逐键 try/catch + 安全默认值，任意键损坏不影响其余功能 |
| 技能名 `C++` 让兜底解析整段崩溃 | 构造正则前统一转义（`new RegExp('C++')` 会抛 `Nothing to repeat`） |
| 同名岗位被误判为已投递而跳过 | 去重指纹从单一「标题-公司名」改为多标识（岗位 ID / 标题-公司名 / 纯标题兜底） |

### 变异测试：证明测试不是摆设

**「测试全绿」不等于「代码正确」** —— 可能只是断言写得太松。所以本项目用变异测试反向验证：

在 `20-core.js` 等文件里**故意注入 48 个缺陷**（去掉去重检查、跳过排除词、改小 `max_tokens`、退回错误的选择器…），逐个确认测试**确实会失败**。

```
PASS  变异测试：48/48 个缺陷被捕获
```

未被捕获的变异会明确报出来 —— 它意味着「我以为在测，其实没测到」。实际开发中，这个机制抓出了 4 处真实的测试盲区，包括：

- `extractJson` 有两个调用点，PDF 那条**完全没有覆盖**
- 断言只查 `!!parsed` 会放过「主解析路径失效、悄悄退到正则兜底」的情况（兜底同样返回非空对象）—— 改用**只存在于 AI 返回中的哨兵值**才分辨得出
- 「只写第一个去重标识」在旧用例下是**等价变异**（那些卡片都没有岗位 ID），需新增同时含 ID 与公司名的用例才能分辨

脚本带双重还原保险（`.mutation-backup` + `try/finally` + 残留检测），任何中断都会告知人工处理，避免污染被固化。

## 设计取舍

**为什么用 `globalThis.__BH__` 命名空间而不是 ES Module？**

MV3 的 `content_scripts` 不支持 `import`（除非用打包器）。多文件按序加载后处于同一隔离世界，用显式命名空间挂载比依赖隐式全局更安全 —— 且能在 `check-content.js` 里断言「依赖链是单向的、无循环引用」。

**为什么模块前缀是 00/01/02/05/10/20/30/40/99 这种数字？**

数字直接决定加载顺序，一眼能看出依赖方向。留空号（如 03、04）是为了将来插入新模块时不必重命名现有文件。

**为什么简历解析要单独做 `extractJson`？**

模型输出不稳定：可能包在 ` ```json ` 围栏里、可能前后带说明文字、可能因 `max_tokens` 偏小被**中途截断**。直接 `JSON.parse` 这三种都会失败。`extractJson` 依次尝试「剥离围栏 → 直接解析 → 截取首尾花括号」，并在截断时给出可读错误（而不是笼统的「解析失败」）。

**为什么排除词要做「误杀/漏杀」双向验证？**

排除词最大的风险不是漏杀，是**误杀** —— 猎头岗 JD 天然出现「电话」「开发客户」等字眼，规则一旦过宽，用户最想投的岗位会被静默过滤掉，界面上只显示「没有符合条件的职位」，极难归因。所以 `test-exclude-keywords.js` 用 9 条应放行 + 9 条应拦住的真实 JD 做双向断言。

## 已知限制

- 依赖 BOSS 直聘的页面结构，平台改版可能导致选择器失效（`05-selectors.js` 标注了验证状态，`selector-audit.js` 可辅助排查）
- 浏览器会对**后台标签页**的定时器降频（隐藏 5 分钟后最多 1 分钟一次），因此长时间无人值守运行建议保持页面在前台
- `lib/pdf.min.js` 与 `lib/pdf.worker.min.js` 为 PDF.js 第三方构建产物，随扩展一同分发
